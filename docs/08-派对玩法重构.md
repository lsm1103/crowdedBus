# 派对玩法重构

> 2026-09 定稿。车模、街景、镜头、车门、惯性都已经可以玩，但整体"不好玩"。
> 本文先诊断原因，再给出新玩法和分阶段计划；第 6 节是第一阶段原型的施工规格。

## 1. 诊断：题材没问题，玩法结构有问题

"挤公交"人人经历过，自带共鸣和喜剧感，和《猛兽派对》《人类一败涂地》这类"笨拙身体 + 互相推搡"的游戏天然契合，题材是加分项。

不好玩的原因（按影响从大到小）：

1. **对手是机器人**。这类游戏的乐趣主要来自真人："我把朋友挤下去了，他在旁边骂"。机器人没有情绪、不记仇、不会求饶。
2. **核心动作"推"不爽**。推一下只是一个带冷却的按钮，没有抓人、拖人、扔人，没有失衡、摔倒。
3. **目标太多太散**。60 秒里塞了座位稳定度、扶手、黄圈、8 种技能、拥挤度、5 种事件、行李、积分等，胜负看抽象分数，最优打法是"坐着刷分"。
4. **大部分时间没有危险**。车门一局只开约 27 秒；完全不动的玩家有 42% 能撑到终点。
5. **看不到热闹**。别人被挤出车门常发生在画面外（镜头本身保留，用其他办法补）。

## 2. 这类游戏好玩的原因（设计原则）

1. **"抓"是万能动作**：抓扶手保命、抓人进攻、抓着人往外拖就是杀招。操作极少，结果极多。
2. **物理带来意外**：好笑来自失控，不来自技能数值。
3. **胜负一眼就懂**：掉出去就输，最后留下的人赢，不看分数。
4. **局短、按回合**：输了马上下一回合，先赢 3 回合拿下整场。
5. **角色没有强弱**：能力一样，外观才是收集动力。
6. **场景会变**：地图机关不断把人往危险里推，逼大家打起来。

## 3. 新玩法

**一句话：车越开越挤，把别人挤下车，最后留在车上的人赢这一回合。**

### 3.1 动作（3 个按钮）

| 按钮 | 空手时 | 抓着人时 | 坐着时 |
|---|---|---|---|
| **抓**（按住） | 抓最近的东西：人优先，其次扶手；靠近空座时点一下是坐下 | 松手就放开 | 点一下起身 |
| **推 / 扔** | 往前撞一下 | 把人朝前方甩出去 | 无效 |
| **冲** | 短距离冲刺，撞到人造成较大失衡 | 拖着人冲一小段 | 无效 |

### 3.2 核心循环："推晕 → 拖走 → 扔下车"

- 每人有一个看不见的**平衡值**（0~1）。被推、被撞、被急刹晃到都会掉，一段时间没被打会慢慢回满。
- 平衡值掉光就**摔倒**，瘫 1.6 秒，这时最容易被抓起来拖走。
- 抓着摔倒的人按"扔"，就把他朝面前甩出去。**从开着的车门甩出去就淘汰**。
- 车门只在到站时开，所以每一站开门的那几秒，就是全车人的击杀窗口。

### 3.3 回合与整场

- 一回合约 90 秒：上车 → 发车 → 途经几站 → 终点前"好挤模式"（两门全开、车身摇摆）→ 到站。
- 回合结束：只剩 1 人，或车到终点。到终点时还在车上的人都算赢这一回合。
- **先赢 3 回合的人拿下整场**。界面只显示"车上还剩几人"和每人的回合胜场，**没有积分**。

### 3.4 场景机关

| 机关 | 发生时机 | 效果 |
|---|---|---|
| 上客潮 | 部分到站 | 涌上来 2~4 个路人乘客，占地方、把人挤来挤去；会抢空座。车越开越挤，相当于"缩圈" |
| 下客潮 | 部分到站 | 1~3 个路人往门外涌，顺手把挡在门口的人带下去 |
| 急刹 / 急转 / 颠簸 | 两站之间 | 全车人往前、往侧面滑，或一起踉跄；只有抓着东西或坐着的人稳得住 |
| 好挤模式 | 终点前约 15 秒 | 两扇门全开，车身左右摇摆 |

### 3.5 座位

按国内城市公交的布局重新排，车厢自然分出前部窄道、中部开阔站立区（主战场）、后部长椅区。
坐着的人最稳，晃不走、推不动，但**坐着不能出手**；别人抓住坐着的人不放 1 秒，就能把他拽起来。坐下是"龟缩还是出手"的取舍。路人乘客也会坐，空座越往后越少。

### 3.6 其他

- **道具代替技能**（第三阶段）：雨伞、菜篮、行李箱、洒了的奶茶等，全员通用。
- **角色改成纯外观**：8 个角色能力完全一样，第一阶段全部开放；以后解锁的是帽子、衣服这类装扮。
- **被淘汰后去站台捣乱**（第二阶段候选）：淘汰的人变成下一站站台上的"等车人"，趁开门把门口的人往外拽。

### 3.7 砍掉 / 保留 / 新增

| 砍掉 | 保留 | 新增 |
|---|---|---|
| 积分系统、黄圈、8 种技能、座位稳定度条、拥挤度条和减速、爱心专座倍率、返场、按成绩解锁角色、行李事件 | 越肩镜头、车模和街景、车门开关、惯性、急刹急转、扶手、座位（重新排布）、摔下车演出、机器人寻路 | 抓人和扔人、平衡值与摔倒、上客潮和下客潮、回合制与整场胜负、坐着被拽起来 |

## 4. 技术策略

1. **物理手感**：规则层继续用二维圆形碰撞模拟（便于联机同步），画面层做"看起来很物理"的表现：被推踉跄、四肢甩动、摔倒瘫软、被拖着晃荡、被扔出去翻滚。不引入三维物理引擎。
2. **联机**：规则层是纯 TypeScript，第二阶段可以原封不动搬到 Node 服务器上作为权威服务器，客户端只上传操作，人不够时机器人补位。第一阶段就要保证规则层不依赖画面层。
3. **复用**：车模、街景、镜头、车门、惯性、机器人寻路、摔下车演出、画面效果都保留；积分、技能、座位规则、黄圈拆掉重写。

## 5. 分阶段计划

| 阶段 | 内容 | 目标 |
|---|---|---|
| 一：玩法原型 | 第 6 节的全部内容，单机 + 机器人 | 自己和机器人打，会不会笑出来 |
| 二：最小联机 | 房间码加入、2~8 人、机器人补位；候选：淘汰后站台捣乱 | 找朋友实际玩几局，记录大家在哪些时刻笑 |
| 三：内容 | 道具、更多线路地图（如双层敞篷巴士）、装扮 | 按试玩结果决定 |

## 6. 第一阶段原型规格

### 6.1 回合时间线（初稿，单位秒）

| 阶段 | 时长 | 说明 |
|---|---|---|
| 上车 boarding | 7 | 站台上车，后门开 |
| 点火 ignition | 2.4 | 关门、起步 |
| 行驶 driving | 约 58 | 途经 4 站，站间 9~13 秒；每站开门 4.5 秒，站型在"上客 / 下客 / 普通"中轮换；两站之间 1~2 个机关（急刹 / 急转 / 颠簸） |
| 好挤模式 finale | 15 | 两门全开、左右摇摆，最后 2 秒减速停靠终点 |
| 结束 ended | — | 只剩 1 人时提前结束（留 1.5 秒给摔出去的演出） |

整场：先赢 3 回合；回合之间 3 秒间歇，显示本回合赢家和胜场。

### 6.2 数值初稿

| 项 | 值 |
|---|---|
| 平衡值 | 上限 1；推中 −0.34（约 3 下摔倒）；冲撞 −0.5；被扔出的人撞到 −0.6；机关按惯性超出"站得住"阈值的部分扣；1 秒没被打后每秒回 0.35 |
| 抓着扶手 | 机关造成的失衡 ×0.3；被推 ×0.5 |
| 摔倒 | 瘫 1.6 秒；爬起后 1 秒内平衡值不低于 0.3（防止被连环按在地上） |
| 推 / 冲冷却 | 0.8 秒 / 2.5 秒 |
| 抓取距离 | 身体表面外 0.6 格，前方 120° 扇形内的人优先，其次扶手 |
| 扯住站着的人 | 双方移速 ×0.5；被扯的人按"推"挣脱，或 1.2 秒后自动挣脱；此时按"扔"只是强推一下 |
| 拖着摔倒的人 | 拖人者移速 ×0.7，被拖的人贴在拖人者前方 0.7 格；被拖的人爬起后再过 0.8 秒挣脱 |
| 扔 | 初速 8 格/秒，滞空 0.45 秒，落地后再瘫 1 秒；飞行轨迹穿过开着的车门就淘汰，撞墙则弹回摔倒 |
| 坐下 / 起身 | 靠近空座按一下"抓"；坐着免疫机关和推挤，不能推、冲、抓 |
| 拽起坐着的人 | 抓住坐着的人不放 1 秒，他被拽起来（平衡值 0.3），直接变成"扯住"状态 |
| 路人乘客 | 半径 0.45、比玩家重（推不太动）、同车最多 8 个；上客站上 2~4 个，优先找空座，其次站在站立区；下客站 1~3 个走向开着的门下车，途中把挡路的人往门外带 |

### 6.3 车厢布局

车厢内部 x∈[−2.35, 2.35]、z∈[−6.2, 6.2]（车头 +z，车门在 +x 一侧），尺寸不变。

座位 6 个（坐标为座垫范围，靠背在"朝向"的反侧）：

| 座位 | 位置 | 朝向 | 座垫 x | 座垫 z |
|---|---|---|---|---|
| 0 | 前部左侧单人座 | 朝车头 +z | −2.30 ~ −1.40 | 4.50 ~ 5.40 |
| 1 | 前部左侧单人座 | 朝车头 +z | −2.30 ~ −1.40 | 3.25 ~ 4.15 |
| 2 | 中部左侧单人座 | 朝过道 +x | −2.32 ~ −1.42 | 0.20 ~ 1.20 |
| 3、4、5 | 后排长椅（三连座） | 朝车头 +z | −2.30~−1.40 / −1.40~−0.50 / −0.50~0.40 | −5.98 ~ −5.10 |

扶手 6 根保持不变。障碍物只保留前门旁的投币箱；婴儿车、行李堆、快递箱和 5 号杆后的填充体删除（车厢里的"障碍物"改由路人乘客承担）。

### 6.4 各层之间的数据约定

规则层（`src/domain`）不引用画面层；画面、界面、会话层只通过下面这些接口读规则层。

**角色状态 `CharacterState`**

| 字段 | 说明 |
|---|---|
| `id` `isPlayer` `defId` `name` `color` `pos` `vel` `facing` `radius` `alive` | 同原来 |
| `status` | `idle` `walking` `dashing` `down`（摔倒）`carried`（被拖着）`thrown`（被扔出去、在空中）`sitting` `eliminated` |
| `balance` | 平衡值 0~1（画面层用来控制踉跄幅度） |
| `downTimer` | 摔倒剩余秒数 |
| `airT` `airDur` | 被扔出去后已飞行时间 / 总滞空时间（画面层画抛物线） |
| `hold` | 我抓着什么：`{ kind: 'rail', id }` / `{ kind: 'char', id }` / `null` |
| `heldBy` | 谁抓着我（id），没有为 `null` |
| `seatId` | 坐着的座位 |
| `dashCd` `pushCd` `stunTimer` | 冷却与被推后的短硬直 |
| `eliminatedOrder` `lastHitBy` `lastHitAt` | 淘汰顺序与击落归属 |
| `throwOuts` | 本回合把几个人扔 / 挤下了车（结算时的趣味数据） |

**路人乘客 `NpcState`**：`id` `pos` `vel` `facing` `radius` `status`（`boarding` `riding` `sitting` `leaving`）`seatId` `look`（外观编号）。下车离开后从列表里移除。

**输入 `InputFrame`**：`move`（世界方向）、`pressed`（本帧按下的键）、`held`（本帧仍按着的键）。按键只有 `grab` `push` `dash` 三个。

**事件 `GameEvent`**（画面、音效、横幅消费）：`banner` `push` `hit` `knockdown` `grab` `release` `throw` `yank`（拽起坐着的人）`sit` `stand` `eliminate`（带 `byId`）`eventStart` `station`（带站型）`npcBoard` `npcAlight` `roundEnd`（带赢家列表）。

**快照 `Snapshot`**：阶段、时间、车速、站名、剩余人数、玩家是否在场、玩家抓着什么、玩家抓着的人是否已摔倒（决定按钮显示"推"还是"扔"）、交互提示（`grab` `sit` `stand` `release`）、6 个座位的占用情况（空 / 玩家 / 机器人 / 路人）、最近空座导航、车门是否开着、玩家平衡值。

**规则层对外的方法**：`setup(roster, seed)`、`applyPlayerInput(frame)`、`tick(dt)` 返回事件、`snapshot()`、`characters`、`npcs`、`layout`、`phase`、`time`、`busSpeed`、`longAccel`、`latAccel`、`tilt`、`stoppingDistance`、`arrived`、`roundResult()`。

**整场 `Match`**（`src/domain/match.ts`）：记录每人的回合胜场，`newRound(seed)` 创建新的一回合模拟，`recordRound(sim)` 记下本回合赢家，`champion` 为先赢 3 回合的人。

### 6.5 验收标准

- 类型检查、冒烟测试通过；平衡探针改写为新规则下的打法对照，并全部通过。
- 规则层（机器人 + 各种玩家打法，大量回合统计）：
  - 每回合平均淘汰 3~5 人，只剩 1 人提前结束的回合占 30%~60%；
  - "完全不动"的玩家回合胜率明显低于"会抓会扔"的打法；只坐不动的打法不能是最优；
  - 平均回合时长 70~95 秒；机器人卡死、单帧瞬移沿用原来的标准。
- 画面：摔倒、被拖、被扔、坐下、路人上下车都有对应表现；被扔出车门时有完整的飞出和落地演出。
- 界面：3 个按钮（抓 / 推·扔 / 冲），没有积分、黄圈、技能；显示剩余人数、回合胜场、回合间歇和整场结算。
- 教学：第一回合依次教会"抓扶手""推人""把摔倒的人扔出车门""坐下与拽人"。
